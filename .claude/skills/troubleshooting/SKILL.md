# 트러블슈팅 문서 작성 가이드

트러블슈팅 과정을 문서화할 때 다음 형식과 규칙을 따릅니다.

## 문서 구조

```markdown
# [문제 제목]

## 개요
- 발생일: YYYY-MM-DD
- 환경: (OS, 버전, 관련 도구 등)
- 상태: 해결됨 / 미해결

## 문제 요약
(문제의 핵심을 1-2문장으로 요약)

## 해결 과정

### [타임스탬프 또는 순서] 사용자 요청
> (사용자의 요청을 있는 그대로 인용)

### [타임스탬프 또는 순서] 분석 및 대응
- **시도한 방법**: ...
- **결과**: ...
- **판단**: ...

(위 패턴을 시간순으로 반복)

## 참고 자료
- 자료명
- ...

## 최종 해결책
(해결된 경우 최종 해결 방법 요약)

## 교훈 및 예방책
(선택: 향후 동일 문제 예방을 위한 조치)
```

## 기록 규칙

### 사용자 요청 기록

- **있는 그대로** 기록합니다.
- 원문을 수정하거나 요약하지 않습니다.
- 인용 블록(`>`)을 사용하여 원문임을 명시합니다.

```markdown
### 1. 사용자 요청
> npm install 실행하면 ERESOLVE 에러가 나는데 어떻게 해결하나요?
```

### 모델 응답 기록

- **논리적 흐름**과 **핵심 내용**을 기록합니다.
- 관련 없는 정보, 인사말, 반복 설명은 생략합니다.
- 다음 항목을 포함합니다:
  - 문제 원인 분석
  - 시도한 해결 방법
  - 각 시도의 결과
  - 다음 단계 판단 근거

```markdown
### 2. 분석 및 대응
- **원인 분석**: 의존성 버전 충돌 (react 18 vs react 17 요구)
- **시도**: `npm install --legacy-peer-deps` 실행
- **결과**: 설치 성공, 빌드 정상 동작
- **판단**: 임시 해결책으로 적용, 장기적으로는 의존성 업데이트 필요
```

### 참고 자료 기록

문제 해결 과정에서 참고한 **모든 자료**를 기록합니다:

- 공식 문서
- Stack Overflow, GitHub Issues 등 외부 링크
- 내부 문서, 코드 파일
- 에러 메시지, 로그 파일

```markdown
## 참고 자료
- npm ERESOLVE 공식 문서
- GitHub Issue #12345
- 프로젝트 내 `package.json` 분석
- 에러 로그: `npm-debug.log` 라인 45-67
```

## 작성 원칙

1. **시간순 기록**: 모든 요청과 응답을 발생 순서대로 기록합니다.
2. **누락 없이**: 사용자의 모든 요청을 빠짐없이 포함합니다.
3. **추적 가능성**: 참고한 모든 자료의 출처를 명시합니다.
4. **재현 가능성**: 동일 문제 발생 시 이 문서만으로 해결할 수 있도록 작성합니다.
